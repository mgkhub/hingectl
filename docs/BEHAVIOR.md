# 実機での挙動と注意点

実機(iPhone Duo)で確かめた内容です。値(待ち時間など)の根拠と、未確認の事項を載せます。使い方は、[README](../README.md) を参照してください。

- ヒンジ角の設定は、Device Hub のヒンジスライダーと同じ vendor-defined HID イベント(usagePage `0xFF61`, usage `0x5B`)で送ります。設定した角度は、コマンドが終了した後も維持されます。
- `orient` / `rotate` は、送信後に向きを繰り返し読み戻して、目標の向きに一致するのを確認します(CoreDevice 側の反映完了まで約 0.4〜0.5 秒)。反映完了が検知された時点で即座にコマンドが終了するため、連続で `rotate` を実行しても確実に 90° ずつ回転します。
  - タイムアウト(`timeout > 0`、既定 2 秒)内に目標の向きに達しなかった場合は、タイムアウトエラー(終了コード 1、標準エラー出力にデバイスやアプリが未対応である可能性と `-t 0` の案内)となります。
  - `-t 0` の場合は確認待ちを行わず、送信流し切り待機(300ms)のみを行って即座に終了します。直後に読み戻した向きが目標と一致しない場合は警告(`hingectl: warning: ...`)を標準エラー出力へ出しますが、終了コードは 0(成功)です。
- 平置き時(机の上などに置かれ、端末の加速度センサーが `faceUp` または `faceDown` を報告している場合)の論理向き判定:
  - 端末が平置きでも相対回転(`rotate left` / `rotate right`)を正しく行えるよう、平置き時はアクティブなディスプレイの描画回転角度(`rotation`)から端末全体の論理向きを逆算します。
  - 通常のディスプレイ(Duo 外側 LCD、iPhone、iPad): `rot0` = `portrait`, `rot90` = `landscape-left`, `rot180` = `portrait-upside-down`, `rot270` = `landscape-right`。
  - iPhone Duo の内側ディスプレイ(`LCD-1`): ハードウェアが標準で横長(rot90)配置されているため、`rot90` = `portrait`, `rot180` = `landscape-left`, `rot270` = `portrait-upside-down`, `rot0` = `landscape-right` となります(実機・シミュレータ実測)。
  - ディスプレイ情報から逆算できない場合(ホーム画面固定など)は、直近の非平置き向き(`currentDeviceNonFlatOrientation`)や設定履歴に安全にフォールバックします。
- `set` / `open` / `close` / `half` / `sweep` は、完了後に読み戻したヒンジ角(`mechanicalAngle`)を標準出力へ出力します(`orient` / `rotate` が変更後の向きを出力するのと一貫性を持たせています)。
  - タイムアウト(`timeout > 0`、既定 2 秒)内に目標の角度に達しなかった場合は、タイムアウトエラー(終了コード 1、標準エラー出力に `-t 0` の案内)となります。
  - `-t 0` の場合は確認待ちを行わず、送信流し切り待機(300ms)のみを行って即座に終了します。直後に読み戻した角度が目標と乖離している場合は警告(`hingectl: warning: the angle read back is ..., not ... (not applied yet, or changed concurrently)`)を標準エラー出力へ出し、読み取れなかった場合は `unknown` を標準出力に出しつつ警告を出しますが、終了コードは 0(成功)です。
- 現在角が `sweep` の `from` と違う場合は、sweep(掃引)の前に `from` へ移動して到達を待ち、UI を載せるディスプレイが切り替わって新しい側が点灯してから 0.5 秒待って、sweep を始めます。待たないと、`from` へ一気に飛んだ直後に sweep が始まり、`from` 側のディスプレイのアニメーションが途中で切られます。実機の Duo では、閉じるとき、UI は約 0.7 秒で背面へ切り替わります(内側のバックライトはその後も約 3.5 秒点いたままですが、それを待つと長すぎたため待ちません)。約 1 秒待っても切り替わらない移動では、そこで待ちを打ち切ります(上限 6 秒)。0.5 秒は、0 / 0.5 / 1 秒を実機で比べて決めました。現在角が `from` と一致する場合と、`-t 0` の場合は、待たずに始めます。
- `sweep` は、開始時刻を基準にした各ステップの目標時刻に合わせて 60Hz で送り、最後に 1 回だけ流し切ります。イベントごとに `sendBarrier()` を呼ぶと、1 回に約 17 ms(往復待ち)かかって実効 26Hz 前後になり、指定の 2.2 倍の時間がかかったため、この方式にしました(実機で計測)。修正後は、デバイスが報告する角度が 200ms ごとに一定(180°→90° を 2 秒なら -9.0°)で動きます。
- ヒンジ角も、送信直後に終了すると反映されませんでした(待ちが 0ms で 0/3 回、50ms 以上で 3/3 回)。`-t 0` や `sweep` の終了前に、300ms 待ってから終了します。確認つきの `set` も、現在値がすでに目標の ±0.5° 以内で、購読の最初の値で確認できたとき(角度が動いたわけではないとき)だけ、送信から 300ms になるまで待ちます(動いて確認できたときは、待ちません)。
- `devicectl device orientation set` は、実機の iPhone Duo では画面が回転しませんでしたが、`hingectl orient` では回転します。
- 未確認: `hingectl set` で設定した角度が、実機を手で動かしたときや再起動したときにどうなるか(設定した値が残り続けるのか、物理ヒンジの値に戻るのか)。
